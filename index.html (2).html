1. Analyse des contraintes

  • Une seule base centrale : tous les appareils (Windows, macOS, Linux, Android, iOS, navigateur) parlent à la même API. Pas de logique métier dans les clients.
  • Fiabilité du matricule : plusieurs secrétaires peuvent inscrire en même temps. La numérotation doit donc être faite par la base, dans une transaction.
  • Connexion internet irrégulière (contexte probable en Haïti) : le mode hors ligne limité est une vraie exigence, pas un bonus. Il est prévu pour la saisie des présences et des notes uniquement.
  • Deux monnaies : chaque paiement garde sa devise d’origine, son taux appliqué et sa contre-valeur. Un taux modifié plus tard ne change jamais un paiement passé.
  • Données d’enfants : accès par rôle, journal d’activité, champs médicaux chiffrés, aucune donnée publique.

4. Matricule : génération sans doublon

Le numéro est pris dans la base, au moment de la validation, dans la même transaction que la création de l’élève. Le UPDATE verrouille la ligne de l’année : deux secrétaires simultanées sont servies l’une après l’autre. Si la transaction échoue, le compteur revient en arrière, donc pas de trou non plus.

CREATE TABLE matricule_sequences (annee INT PRIMARY KEY, dernier INT NOT NULL DEFAULT 0);
ALTER TABLE eleves ADD CONSTRAINT eleves_matricule_uk UNIQUE (matricule);

-- dans la transaction de validation d'inscription
INSERT INTO matricule_sequences (annee, dernier) VALUES (2026, 1)
ON CONFLICT (annee) DO UPDATE SET dernier = matricule_sequences.dernier + 1
RETURNING 'SGSM-' || annee || '-' || lpad(dernier::text, 4, '0') AS matricule;

Le matricule est ensuite protégé en écriture par un déclencheur (BEFORE UPDATE qui refuse toute modification). Une réinscription ou un changement de classe crée une ligne dans inscriptions et ne touche jamais le matricule.

7. Remontée des données vers Google Sheets

Principe : la base PostgreSQL reste la source de vérité. Google Sheets est un miroir en lecture, alimenté à sens unique. Chaque changement important (inscription, paiement, note, absence) est inscrit dans une file export_queue dans la même transaction, puis un worker l’envoie à Google. Si internet tombe, rien n’est perdu : l’envoi reprend plus tard.

Étape 1 — Créer le fichier Google Sheets

  1. Dans Google Drive : Nouveau → Google Sheets, nommez-le SGSM_Export.
  2. Créez les onglets Eleves, Paiements, Notes, Presences.
  3. Ligne 1 de chaque onglet, colonne A toujours = clé unique :
    • Eleves : matricule | nom | prenom | sexe | classe | annee | statut | maj
    • Paiements : reference | matricule | montant | devise | taux | montant_usd | date | maj
    • Notes : cle | matricule | matiere | evaluation | note | bareme | date | maj
    • Presences : cle | matricule | date | statut | motif | maj
  4. Ne partagez ce fichier qu’avec la direction : il contient des données d’élèves.

Étape 2 — Installer le récepteur (Google Apps Script)

  1. Dans le fichier : Extensions → Apps Script. Supprimez le contenu et collez :
function doPost(e) {
  const lock = LockService.getScriptLock();
  lock.waitLock(20000);
  try {
    const p = JSON.parse(e.postData.contents);
    const secret = PropertiesService.getScriptProperties().getProperty('SGSM_TOKEN');
    if (p.token !== secret) return rep({ ok: false, erreur: 'non autorise' });

    const ss = SpreadsheetApp.getActiveSpreadsheet();
    const sh = ss.getSheetByName(p.feuille);
    if (!sh) return rep({ ok: false, erreur: 'feuille inconnue: ' + p.feuille });

    const entetes = sh.getRange(1, 1, 1, sh.getLastColumn()).getValues()[0];
    const n = sh.getLastRow();
    const cles = n > 1 ? sh.getRange(2, 1, n - 1, 1).getValues().flat().map(String) : [];

    p.lignes.forEach(function (obj) {
      const ligne = entetes.map(function (h) { return obj[h] === undefined ? '' : obj[h]; });
      const i = cles.indexOf(String(ligne[0]));
      if (i === -1) {                      // nouvelle clé : on ajoute
        sh.appendRow(ligne);
        cles.push(String(ligne[0]));
      } else {                             // clé connue : on met à jour (pas de doublon)
        sh.getRange(i + 2, 1, 1, ligne.length).setValues([ligne]);
      }
    });
    return rep({ ok: true, recu: p.lignes.length });
  } finally {
    lock.releaseLock();
  }
}
function rep(o) {
  return ContentService.createTextOutput(JSON.stringify(o)).setMimeType(ContentService.MimeType.JSON);
}
  1. Engrenage Paramètres du projet → Propriétés du script → Ajouter : nom SGSM_TOKEN, valeur = une longue chaîne aléatoire (générez-la avec openssl rand -hex 32). Gardez-la, elle ira dans le .env du serveur.
  2. Déployer → Nouveau déploiement → type « Application Web ». Exécuter en tant que : Moi. Qui a accès : Tout le monde (le jeton secret protège l’accès). Autorisez les droits demandés.
  3. Copiez l’URL de l’application Web (elle se termine par /exec).

Étape 4 — File d’envoi dans PostgreSQL

CREATE TABLE export_queue (
  id          BIGSERIAL PRIMARY KEY,
  feuille     TEXT NOT NULL,          -- Eleves, Paiements, Notes, Presences
  cle         TEXT NOT NULL,          -- matricule, reference de paiement, ...
  payload     JSONB NOT NULL,         -- la ligne à écrire
  statut      TEXT NOT NULL DEFAULT 'attente',  -- attente | envoye | erreur
  tentatives  INT  NOT NULL DEFAULT 0,
  erreur      TEXT,
  cree_le     TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX ON export_queue (statut, id);

Le service métier ajoute la ligne dans la même transaction que l’opération (inscription validée, paiement enregistré, etc.) : si l’opération est annulée, l’export l’est aussi.

Étape 5 — Worker d’envoi (Node.js, toutes les 60 s)

// export-sheets.worker.ts
export async function envoyerVersSheets(db) {
  const { rows } = await db.query(
    `SELECT id, feuille, payload FROM export_queue
     WHERE statut = 'attente' ORDER BY id
     LIMIT $1 FOR UPDATE SKIP LOCKED`, [Number(process.env.GSHEETS_BATCH)]);
  if (!rows.length) return;

  const parFeuille = {};
  rows.forEach(r => (parFeuille[r.feuille] ??= []).push(r));

  for (const [feuille, items] of Object.entries(parFeuille)) {
    const ids = items.map(i => i.id);
    try {
      const res = await fetch(process.env.GSHEETS_URL, {
        method: 'POST',
        headers: { 'Content-Type': 'text/plain;charset=utf-8' },
        body: JSON.stringify({
          token: process.env.GSHEETS_TOKEN,
          feuille,
          lignes: items.map(i => i.payload),
        }),
      });
      const r = await res.json();
      if (!r.ok) throw new Error(r.erreur);
      await db.query(`UPDATE export_queue SET statut='envoye' WHERE id = ANY($1)`, [ids]);
    } catch (e) {
      await db.query(
        `UPDATE export_queue SET tentatives = tentatives + 1, erreur = $2,
         statut = CASE WHEN tentatives >= 9 THEN 'erreur' ELSE 'attente' END
         WHERE id = ANY($1)`, [ids, String(e.message)]);
    }
  }
}
// planifié avec @nestjs/schedule : @Interval(60000)

Points importants : SKIP LOCKED évite que deux instances envoient les mêmes lignes ; text/plain évite un blocage de type CORS ; la clé en colonne A rend l’envoi idempotent (renvoyer deux fois met à jour la ligne au lieu de la dupliquer).

Étape 6 — Ce qui est envoyé (et ce qui ne l’est pas)

  • Envoyé : matricule, nom, prénom, classe, statut, paiements, notes, présences.
  • Jamais envoyé : informations médicales, téléphones des parents, documents, photos, mots de passe.
  • Pour une première reprise (élèves déjà présents), un bouton administrateur « Exporter tout » remplit la file avec toutes les lignes existantes.

Étape 7 — Tester

  1. Inscrivez un élève de test : en moins d’une minute, une ligne SGSM-2026-0001 apparaît dans Eleves.
  2. Modifiez sa classe : la même ligne est mise à jour, sans nouvelle ligne.
  3. Coupez internet côté serveur, enregistrez un paiement, rétablissez : le paiement arrive dans la feuille.
  4. Envoyez une requête avec un mauvais jeton : réponse « non autorisé », rien n’est écrit.
Limites à connaître. Apps Script plafonne le volume d’appels par jour et reste lent au-delà de quelques dizaines de milliers de lignes par feuille. Pour une école, c’est largement suffisant ; au-delà, on passera à l’API Google Sheets avec un compte de service (même file, seul le worker change). Google Sheets sert à consulter et analyser : ne modifiez pas les données dans la feuille, elles seraient écrasées au prochain envoi.

8. Questions avant validation

  1. Le serveur sera-t-il hébergé en ligne (VPS) ou dans l’école, sur un ordinateur local ?
  2. Combien d’élèves environ, et combien de secrétaires saisiront en même temps ?
  3. Le barème des notes (sur 10, 20, 100) et les périodes (trimestres, étapes) sont-ils les mêmes pour tous les niveaux ?
  4. Faut-il les deux devises sur chaque reçu, ou la devise payée seulement ?
  5. L’école a-t-elle déjà des données (Excel) à importer ?

Dès votre validation, je passe à l’étape 1 du plan : fondations, base PostgreSQL et authentification.
